## 8. Findings for the smart-pi coding session

**SmartPI**

- **F1 — extended: the diagnostics are not written when the dependency layer's state changes.**
  Phase A showed it for the water source.
  - **Where the write is triggered:** the diagnostic sensor writes on the VTherm climate's state
    changes and on a forced update (`sensor.py` `_update_from_climate` / `_async_force_update`;
    `handler.py` lines 945 and 1230, as the phase A report gives them).
  - **Changes that force no write** (phase C):
    - a door connecting a neighbour (QD4): delays of 225 s and 148 s, against the pack's 150 s;
    - a second source taking its role back (QE3): SmartPI changed it at 06:29:01, and the floor's
      diagnostics were next written at 06:39:01, one VTherm cycle later;
    - QE2, which failed on the same missing write.
  - **Suggested:** force a write whenever the dependency block's published state changes: a
    neighbour's connection, a source's role, the window action, the learning gate, the water
    source, the boiler's call.
  - **Effect:** with that fix, P11, P12 and P17 need no longer waits.
- **F2 — `emitter_cooling` not seen within the pack's wait (QC2s): still open.**
  - QW5 saw it within the wait in phase C; QC2s did not, in phase A or phase C.
  - SmartPI's actual transition time is not recorded, and F1 is the likely cause.
  - Please check the transition in `boiler_call.py` against the grace, and have the pack record when
    the state is first seen.
- **F6 — withdrawn** (section 4.2). Nothing in phase C shows the floor's fallback reacting badly: it
  took over on time and ran at 100 % in a room that had been reset to 19.0 °C.
- **F9 (minor, low priority) — a learning reset does not reset AutoCalib's snapshot.**
  - `reset_learning` (`algo.py` from line 488) resets the estimators, the dependency model and the
    controller, but not `self.autocalib`.
  - After QA3's reset during a running calibration, the exit check counted new updates from the old
    snapshot: "partial exit (retry 1/3, missing=['a(new=-17<1)', 'b(new=-9<1)', 'deadtime_heat'])"
    at 06:54:34 (`autocalib.py` 625–695).
  - It recovered by itself: a retry at 09:38:40, a positive exit (improved `b`) at 11:46:03, and
    `model_degraded` false.
  - Suggested: take a new snapshot (or cancel the pending exit check) when learning is reset.
